# Методика v16

Комплект отвечает на ТЗ «Доработка системы извлечения геологических знаний и территориально-ориентированного поиска». Все скрипты только читают базу `georag_v14`. Это копия рабочей базы; рабочая база `georag` и ветка `main` не менялись. Версии библиотек, модели и параметры записаны в `code/requirements.txt` и `code/configs/eval.json`.

## Запуск

```bash
.venv/Scripts/python.exe -X utf8 research/v16/reproduce_results.py
```

Перед запуском поднимите базу (`docker start georag-db`). Языковая модель для запуска не нужна: место и понятия вопросов берутся из сохранённых прогонов v15. Время запуска — около 30 мин. Почти всё оно уходит на однократный расчёт векторов 6 389 связей без векторов; расчёт идёт на CPU, результат кешируется в `.cache/`.

## Задача 1. Воронка связей

Этапы названы по фактическому коду `georag/graph`:

1. **extraction.** Модель qwen3:14b предлагает связи (`facts.py`).
2. **code_check.** Код проверяет связь (`facts.check`, `facts.recheck`):
   - форму ответа;
   - что оба имени есть в предложении-основании;
   - номер предложения;
   - правила «не предмет».
3. **confirmation.** Связь проходит, если выдержала не менее 3 из 4 контрольных вопросов (`confirm.py`) или её концы связаны и в другой статье (`store.accepted`). Иначе она остаётся кандидатом.
4. **typing.** Модель выбирает тип из 14 типов или «нет», затем код проверяет виды концов (`kinds.py`). Связь без типа в граф не входит (`store.all_facts`).

Каждая связь из таблицы `facts` проходит в CSV по строке на этап. Отклонённые на шаге 2 связи в `facts` не записываются, от них есть только строки причин в `facts_pass.rejected`. В CSV они получают построенные идентификаторы `R<фрагмент>-<n>`.

В графе 3 818 связей. Итоговое отношение (`final_relation_id`) — тройка (объект, тип, объект) после словаря синонимов и автосинонимов; таких троек 3 783.

## Задача 2. Ошибки извлечения

- **Основа.** Ручная разметка автора: 120 случайных связей графа, лист «Факты» в `research/v15/Разметка_v15_автор.xlsx`.
- **Категории ошибок.** Заданы по комментариям автора, отдельно для каждой строки (`CATEGORY` в скрипте).
- **Модальность.** Текущее правило кода `facts.hedged` сравнивается с правилом, где список оборотов предположения расширен. Расширение подобрано по тем же 120 связям, поэтому его результат на них — не оценка. Для оценки нужна разметка листа «Модальность».
- **Отрицания.** Связь отбирается на проверку, если в цитате есть отрицание, а в самой связи его нет. Это отбор, а не мера ошибок.

## Задача 3. Предварительный фильтр

Выборка — 150 фрагментов, по 25 из каждой группы по числу терминов словаря: 0, 1, 2, 3, 4, 5 и больше. Дубликаты и подписи к рисункам в выборку не входят: их отсеивает другое правило при любом пороге. Размечающий не видит числа терминов и извлечённых связей.

Для порога t отсеиваются группы с числом терминов меньше t. Доля фрагментов со связями в группе берётся из разметки и переносится на всю группу в корпусе. Так получаются:
- `relation_recall` — доля фрагментов со связями, которые порог сохраняет;
- `missed_relations` — оценённое число фрагментов со связями среди отсеянных.

Экономия токенов оценивается по длине отсеянных фрагментов. Прямой замер для порога 3 на 100 фрагментах дал 21,3 %.

## Задачи 5–6. Поиск

- **Вопросы.** Оба набора, проверенных автором: 89 и 84 вопроса, без изменений. Релевантны статья и фрагмент, по которым составлен вопрос.
- **Варианты поиска.** Описаны в начале `retrieval_eval.py`:
  - B0–B4 — территориальные варианты;
  - `+gf` и `+gn` — графовые кандидаты;
  - абляции графа.
- **Слияние кандидатов.** Графовые кандидаты добавляются к выдаче поиска по смыслу третьим списком через RRF (k = 60). В выдаче на один источник приходится не больше двух фрагментов.
- **Происхождение фрагмента.** Для каждого фрагмента в первой пятёрке записано, кто его нашёл: вектор, граф или оба (`found_by` в `retrieval_results.csv`).
- **Метрики:**
  - статья среди первых пяти;
  - статья первой;
  - фрагмент среди первых пяти;
  - MRR@10 по статьям;
  - медианное время на вопрос без разбора вопроса моделью.
- **Неопределённость.** Парная разность с бутстрэпом (10 000 повторов, зерно 1). По объединённому набору повторы делаются по статьям: из одной статьи может быть по вопросу в каждом наборе.
- **Сверка с v15.** B1 и B3 на наборе 89 должны совпасть с `vector` и `vector+place` из `research/v15/results/ablation.json`.
