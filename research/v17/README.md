## Какие выводы остаются подтверждёнными

- Предварительный фильтр теряет часть содержательных фрагментов. Ретроспективная проверка по графу (1,8 %) этого не показывает: у неё другой знаменатель.
- Типизация напрасно исключила 33 из 60 проверенных связей (0,55; интервал 0,42–0,67).
- 104 из 120 принятых связей соответствуют тексту. Отрицания переданы верно в 83 из 85 случаев. Расширенное правило предположений точно только в 56 из 98 случаев.
- Территориальное ограничение улучшает поиск известного источника: B2t против B1 даёт +0,075, интервал 0,036–0,118. Дополнительный эффект сопоставления написаний мал и не установлен.
- Графовые кандидаты на этом наборе вопросов поиск не улучшили.
- **Общий вывод:** качество построения геологической базы знаний нужно проверять независимой оценкой потерь на отдельных стадиях. Метрики конечного графа и поиска её не заменяют (табл. 4 статьи).

## Что не удалось устранить

- **Короткие фрагменты (123) не размечены.** Лист готов: «Короткие» в `Разметка_v17.xlsx`. После разметки сохраните его как `Разметка_v17_проверено.xlsx` и выполните `reproduce_results.py --files-only`: оценка для всей области, документы и статья пересоберутся.
- **53 связи без типизации не оценены вручную.** Лист «Без типизации» там же. Повторная типизация моделью не заменяет ручную оценку.
- **Система не исправлялась** — это изменение рабочего кода. Не сделаны: типизация всех принятых связей, исключение повторов между версиями одной работы, пересмотр правил типизации.
- **Извлечение с полями modality и polarity** и **набор вопросов специалистов** не выполнялись.
- **Литература.** Источник [16] впервые упомянут раньше [11]. При строгой нумерации по порядку упоминания нужна перенумерация.

## Команды

```bash
docker start georag-db
.venv/Scripts/python.exe -X utf8 research/v17/reproduce_results.py               # все шаги
.venv/Scripts/python.exe -X utf8 research/v17/reproduce_results.py --files-only  # без базы
```

Скрипты рассчитаны на запуск из репозитория. Распакуйте `code/source/source_01c8fdf.zip`, положите содержимое `code/evaluation/` (вместе с `.cache/`) и `code/reproduce_results.py` в `research/v17/`, а листы разметки из `results/` — туда же. Кеш фрагментов в архиве без текстов статей: для шагов `--files-only` тексты не нужны. Какие шаги требуют базы, а какие нет, — в `docs/reproducibility_report.md`. Итоговые таблицы собирает `figures.py`, проверки — `checks.py` (22 проверки, все пройдены).

## Эксперименты после ИПУЗ

1. **Набор вопросов специалистов**, ответ на которые требует объединения нескольких связей. Только на нём сравнивать векторный, графовый и гибридный поиск. Схему объединения фиксировать до запуска.
2. **Исправление системы на копии базы** с последующей оценкой: типизация всех принятых связей, учёт версий одной работы при подтверждении повтором, пересмотр правил типизации.
3. **Оценка пропусков на уровне отдельных связей**, а не фрагментов. Разметка вторым разметчиком.
4. **Извлечение с полями модальности и полярности.**
5. **Проверка территориальной применимости:** прямое свидетельство / аналогия / нехватка данных.
