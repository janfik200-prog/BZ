# Проверка прослеживаемости на другой базе

Скрипт `trace_audit.py` считает все числа для отчёта о прослеживаемости, прозрачности и
обоснованности. Базу он только читает. Здесь — что сделать на базе, где статей больше и
графа ещё нет.

## 1. Построить граф

Граф строит Qwen3-8B с проверками кода (строгий режим), как в этой базе:

```
python georag.py graph --limit 30      проба: 30 фрагментов, посмотреть, что всё работает
python georag.py graph                 весь граф; прерванный запуск продолжает с места
```

Если векторов ещё нет (статьи только загружены) — `python georag.py build`: сначала
векторы, потом граф. Подтверждение вопросами, сведение имён и темы идут сами после `graph`.

## 2. Проверить граф (нужна Qwen3-8B, порт 8101)

```
python research/trace_audit/trace_audit.py --sample 2000
```

`--sample 2000` — четыре вопроса к цитате задаются 2000 случайным связям (на 2000 связях
интервал доли ± 2 %). Все связи — без `--sample`, но это часы.
Проверка на 120 размеченных связях (`gold_120.csv`) идёт сама: от базы она не зависит.

## 3. Проверить ответы чат-бота (нужна Qwen3-14B, порт 8100)

Обе модели сразу на 16 ГБ не помещаются: остановить 8B, поднять 14B.

```
python research/trace_audit/trace_audit.py --only-chat --chat 30
```

Вопросы — из `config/eval-questions.yaml` (ожидание «база»). Если в базе другие статьи,
лучше дописать туда вопросы о них.

## 4. Что принести обратно

Папку `research/trace_audit/results/`: `summary.json` (все числа), `report.md` (то же
словами), `facts.csv` (вердикт по каждой связи), `gold_check.csv`, `chat.csv`. По
`summary.json` числа в отчёте заменяются один к одному.
