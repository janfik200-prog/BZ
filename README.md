# Агентная база данных проекта прогноза золото-урановых узлов

Отдельная задача со своим репозиторием: база, в которой собраны данные проекта,
их паспорта, происхождение каждого числа и решения человека о том, чему можно
верить. Заполняют её агенты, подтверждает человек — и база устроена так, чтобы
обойти это правило было нельзя.

Основной репозиторий проекта (`GIS`) считает признаки и строит прогноз; здесь
они описываются, проверяются и хранятся. Связь между репозиториями — ссылкой на
каталог проекта (`gisdb/project.py`, переменная `GIS_PROJECT_ROOT`), без
копирования данных.

## Из чего состоит

| Каталог | Что внутри |
|---|---|
| `db/` | миграции `sql/001`–`010`, резервное копирование, проверка восстановления, подробный README |
| `gisdb/` | подключение и пароли, запись в базу, единая точка обращения к модели, факты о признаке, панель подтверждений |
| `scripts/` | наполнение базы, агент-паспортизатор, сборка презентации и рисунков |
| `tests/` | 61 проверка: правила базы, исполнитель-модель, панель |
| `docs/` | презентация по агентной базе |

## С чего начать

Устройство базы, установка, роли, миграции, правила подтверждения, панель и
перенос на сервер описаны в [`db/README.md`](db/README.md) — это главный
документ. Коротко:

```
python -m pytest tests -q                  # 61 проверка, сеть не нужна
python -m gisdb.panel                      # панель подтверждений на 8765
python db/backup.py                        # дамп базы, ролей и записки
python db/restore_check.py                 # копия доказывается восстановлением
python scripts/db_agent_passporter.py      # агент описывает смысл признаков
```

## Правила, ради которых всё это

* статус «подтверждён» ставит только человек — у агента нет такого права, и
  триггер в базе не даст его обойти;
* каждое обращение к модели записано: модель, отпечаток её весов, токены,
  время, число попыток и сам ответ;
* агент не удаляет данные за пределами черновой схемы;
* пароли лежат вне репозитория — в `F:\GIS-DB\secrets`.
