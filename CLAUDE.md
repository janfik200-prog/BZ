# Агентная база данных — правила работы

## Что это
База данных проекта прогноза золото-урановых узлов: данные, их паспорта,
происхождение каждого числа и решения человека о том, чему верить. Узлы 3
(«Агентная сборка базы данных») и 4 («Подготовка и паспортизация данных»)
технологической схемы. Основной репозиторий проекта — `GIS`, он считает
признаки и строит прогноз; связь только односторонняя, через
`gisdb/project.py` и переменную `GIS_PROJECT_ROOT`.

Подробное устройство — `db/README.md`. Это главный документ, а не этот файл.

## Незыблемые правила
- **Статус «подтверждён» ставит только человек.** Агент пишет черновики;
  триггер в базе не даст обойти это ни скриптом, ни правкой напрямую.
- **Агент не удаляет данные** за пределами черновой схемы: у роли
  `gis_agent` нет права DELETE.
- **Пароли только в `F:\GIS-DB\secrets`** и не попадают в репозиторий.
- **Каждое обращение к модели записывается** в `runs.llm_call` целиком:
  исполнитель, модель, отпечаток весов, токены, время, попытки, ответ.
- **Шлиховые пробы золота — не рудопроявление**, это разные категории точек.

## Как писать
- Ответы, код, комментарии, сообщения коммитов — **по-русски**.
- В презентациях и отчётах — без англоязычных калек и без слова «честный».
- Во внешних документах — «организация», а не «заказчик».
- Комментарий объясняет **почему** так сделано, а не пересказывает код.
- Коммит — по одному логическому изменению, без подписей и трейлеров сверх
  оговорённых.

## Проверки
```
python -m pytest tests -q        # 61 проверка; сеть и модель не нужны
```
Проверки правил базы работают с живой базой на 5433 и не оставляют следов:
решения человека пишутся только в подменённом соединении.

## Исполнитель-модель
Единая точка — `gisdb/agent_llm.py`. По умолчанию ищется локальный сервер
(Ollama на 11434, llama.cpp на 8080, LM Studio на 1234), иначе облако по
ключу, иначе средство разработки. Для локальной модели обязательна настройка
`GIS_LLM_REASONING=none` — иначе каждый ответ стоит вшестеро дороже.
