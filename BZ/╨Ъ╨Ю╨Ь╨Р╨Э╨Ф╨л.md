# ГеоRAG — все команды

Шпаргалка. Всё выполняется в PowerShell, из папки проекта:

```powershell
cd C:\Users\Janfik\Desktop\georag
```

Есть два способа: короткий — через `georag.ps1`, и полный — вызовом Python напрямую.
Короткий удобнее каждый день, полный нужен, когда хочется покрутить настройки.

---

## 0. Один раз при первом запуске на новой машине

```powershell
# Python 3.12 с python.org, при установке галочка «Add python.exe to PATH»
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# Torch с поддержкой видеокарты (для RTX 50-й серии — cu128)
.\.venv\Scripts\python.exe -m pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"   # должно быть True

# Разрешить запуск скриптов (нужно один раз для georag.ps1)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# База и модель отбора
docker compose up -d
.\georag.ps1 init
ollama pull qwen3:14b
```

## 1. Ежедневный цикл

| Что делаем | Коротко | Полностью |
|---|---|---|
| Поднять базу | `.\georag.ps1 start` | `docker compose up -d` |
| Добыть по одной теме | `.\georag.ps1 add "выделение рудных узлов"` | см. ниже |
| Добыть по всем темам | `.\georag.ps1 all` | см. ниже |
| Посмотреть, что не по теме | `.\georag.ps1 clean` | `.\.venv\Scripts\python.exe scripts\clean_acquired.py` |
| Убрать не по теме | `.\georag.ps1 clean -Apply` | `... scripts\clean_acquired.py --apply` |
| Загрузить в базу | `.\georag.ps1 ingest` | `.\.venv\Scripts\python.exe -m georag.index.cli ingest` |
| То же, но векторы через Ollama | `.\georag.ps1 ingest -Ollama` | `... cli ingest --embedder ollama` |
| Поискать | `.\georag.ps1 search "рудные узлы"` | `.\.venv\Scripts\python.exe -m georag.index.cli search "рудные узлы"` |
| Построить связи | `.\georag.ps1 graph` | `.\.venv\Scripts\python.exe -m georag.graph.cli build` |
| Связи с разбором моделью | `.\georag.ps1 graph -Llm` | `... graph.cli build --llm` |
| Поиск в браузере | `.\georag.ps1 web` | `.\.venv\Scripts\python.exe -m georag.web.server` |
| Что в базе | `.\georag.ps1 stats` | `.\.venv\Scripts\python.exe -m georag.index.cli stats` |
| Остановить базу | `.\georag.ps1 stop` | `docker compose stop` |

Порядок всегда один: **добыть → почистить → загрузить → связи → искать.**

## 2. Добыча статей — полная команда

```powershell
.\.venv\Scripts\python.exe -m georag.acquire.cli "выделение рудных узлов" `
    --max-docs 5 --no-ocr --device cuda `
    --mailto tracybowmanpowxzfwl@outlook.com --model qwen3:14b
```

По всем темам сразу — вместо темы в кавычках подставить `--topics topics.yaml`.

Что означают ключи:

| Ключ | Зачем |
|---|---|
| `--topics topics.yaml` | взять список тем из файла вместо одной темы |
| `--max-docs 5` | сколько статей разбирать за тему |
| `--no-ocr` | не распознавать картинки — быстрее в разы, для обычных статей не нужно |
| `--device cuda` | считать на видеокарте |
| `--mailto ...` | вежливый режим OpenAlex и Crossref: ответы стабильнее |
| `--model qwen3:14b` | какая модель в Ollama отбирает статьи |
| `--no-llm` | не спрашивать модель, решать эвристикой (когда Ollama выключена) |
| `--dry-run` | только поиск и отбор, без скачивания — быстрая проверка |
| `--force` | не пропускать статьи, которые уже видели |
| `--tables fast` | быстрый разбор таблиц вместо точного |
| `--per-query 25` | сколько результатов брать из каждого источника |

Только запросы, без поиска — посмотреть, что модель придумала по теме:

```powershell
.\.venv\Scripts\python.exe -m georag.acquire.cli "рудные узлы" --queries-only
.\.venv\Scripts\python.exe -m georag.acquire.cli --topics topics.yaml --queries-only --save-queries queries.yaml
```

Файл `queries.yaml` можно править руками, а потом искать по нему,
не дёргая модель каждый раз:

```powershell
.\.venv\Scripts\python.exe -m georag.acquire.cli --topics topics.yaml --queries-file queries.yaml
```

## 3. Поиск — полная команда

```powershell
.\.venv\Scripts\python.exe -m georag.index.cli search "гидротермальные изменения ASTER" `
    --limit 10 --per-doc 2 --year-from 2015
```

| Ключ | Зачем |
|---|---|
| `--limit 10` | сколько результатов показать |
| `--per-doc 2` | не больше N кусков одной статьи (0 — без ограничения) |
| `--year-from 2015` | только статьи не старше указанного года |
| `--source openalex` | искать только по одному источнику |
| `--candidates 50` | сколько кандидатов брать из каждого поиска до объединения |
| `--min-similarity 0.45` | отсечь непохожее: 0.45 — обычно, 0.55 — строго, 0 — показывать всё |
| `--require-words` | только куски, где буквально есть все слова запроса |
| `--embedder ollama` | считать вектор запроса через Ollama, а не на видеокарте |

Векторный поиск всегда возвращает ближайшее — даже когда подходящего в базе нет.
Поэтому есть порог: `--min-similarity`. У BGE-M3 текст про то же самое даёт похожесть
примерно от 0.6, случайный сосед — около 0.3–0.45. Куски, где буквально есть все слова
запроса, проходят порог всегда: совпадение по словам само по себе доказательство.

В выдаче у каждого результата написано, **кто его нашёл**: «вектор» — по смыслу,
«текст» — по точным словам, «оба» — согласились оба способа. «Оба» — самый
надёжный признак.

## 3а. Поиск в браузере

```powershell
.\georag.ps1 web
```

Открывает `http://localhost:8000`. Та же база и тот же гибридный поиск, что
в команде `search`, но модель эмбеддингов грузится один раз при запуске, а не
на каждый запрос, — поэтому поиск отвечает мгновенно и можно спокойно пробовать
формулировки. Остановить — Ctrl+C в том же окне PowerShell.

Сервер слушает только localhost: из сети к нему не подключиться.

## 3б. Связи между статьями

```powershell
.\georag.ps1 graph
```

Проходит по всем фрагментам в базе и вытаскивает названия: рудные узлы, поля,
районы, месторождения, площади, а также полезные ископаемые и методы. Строится
с нуля каждый раз — правила извлечения меняются, и старые названия иначе не убрать.
Сеть и модели для этого не нужны.

Посмотреть из терминала:

```powershell
.\.venv\Scripts\python.exe -m georag.graph.cli top
.\.venv\Scripts\python.exe -m georag.graph.cli top --kind метод
.\.venv\Scripts\python.exe -m georag.graph.cli near "Анабарский щит"
```

Или во вкладке «Связи» в браузере. **Связь означает ровно одно: об этих двух
написано в одной статье.** Ничего не додумано — за каждой связью стоит список
статей, который можно открыть.

Названия достаются правилами по опорным словам: «…ский рудный узел», «…ское
рудопроявление», «…ская зона».

### Разбор моделью

```powershell
.\georag.ps1 graph -Llm
```

Требует работающей Ollama и идёт заметно дольше — примерно две-три секунды
на фрагмент, то есть на трёхстах фрагментах около четверти часа. Взамен даёт
то, чего правила не умеют:

- имена в любом порядке слов — «трубка Удачная», «месторождение Сухой Лог»;
- **названные связи**: не просто «упомянуты вместе», а «находится в»,
  «приурочено к», «применён к». Они показываются отдельным блоком «связи из текста».

Модель не заменяет правила, а дополняет их: ключи у сущностей общие, поэтому
найденное обоими способами схлопывается. Если Ollama молчит, сборка не падает —
остаётся то, что нашли правила.

## 4. База данных

```powershell
docker compose up -d          # поднять (первый раз — создаёт)
docker compose start          # поднять существующую
docker compose stop           # остановить, данные остаются
docker compose ps             # что сейчас работает
docker compose logs db        # что пишет база, если не поднимается
```

**Никогда:** `docker compose down -v` — эта команда удаляет том с базой,
и всё придётся индексировать заново.

Переиндексировать всё с нуля, не трогая добытые статьи:

```powershell
.\.venv\Scripts\python.exe -m georag.index.cli ingest --force
```

## 5. Ollama

Ollama отвечает за языковую работу: отбор статей и составление запросов.
Векторы считаются локально на видеокарте — так быстрее и не зависит от того,
запущена ли служба. Гонять их через Ollama можно ключом `-Ollama`, но смысла мало.

```powershell
ollama list                   # какие модели скачаны
ollama pull qwen3:14b         # отбор статей и составление запросов
ollama pull bge-m3            # нужна только если считать векторы через Ollama
ollama ps                     # что сейчас в памяти
ollama stop qwen3:14b         # выгрузить из видеопамяти
```

Модель выгружается сама примерно через пять минут простоя.

## 7. Что где лежит

```
georag\
    georag.ps1              ← этот короткий вход
    КОМАНДЫ.md              ← эта шпаргалка
    topics.yaml             ← темы поиска: правьте свободно
    sources.yaml            ← где искать: добавить источник можно без кода
    docker-compose.yml      ← описание базы
    requirements.txt        ← список библиотек
    georag\                 ← сам код
        acquire\            ← добыча: поиск, отбор, скачивание
        index\              ← база: векторы, поиск
        graph\              ← связи: названия и упоминания
        web\                ← страница поиска в браузере
    scripts\                ← вспомогательные скрипты
    tests\                  ← проверки кода
    data\acquired\          ← добытое: ссылки, тексты, чанки
    logs\                   ← логи прогонов
```

Самих PDF нигде нет — так и задумано. Хранятся ссылка, отпечаток файла
и разобранный текст.

## 8. Если что-то сломалось

| Симптом | Что делать |
|---|---|
| `python.exe не распознано` | вы не в папке проекта либо нет `.venv` — см. раздел 0 |
| `База недоступна` | `docker compose ps`, потом `docker compose up -d` |
| Контейнер `Restarting` | `docker compose logs db` — там причина |
| `выполнение сценариев отключено` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| Ollama не отвечает | `ollama list`; если пусто — `ollama pull qwen3:14b`; временно можно с `--no-llm` |
| `llama-server binary not found` | установка Ollama повреждена — переустановить поверх с ollama.com/download; модели сохранятся |
| «ожидался вектор на 1024 числа» | в Ollama не та модель векторов — нужна именно `bge-m3` |
| Статьи не скачиваются (403) | это защита издателя или платный доступ, лечится не всегда |
| Кракозябры в логе | читать с явной кодировкой: `Get-Content ... -Encoding utf8` |
