# ГеоRAG — как запустить

Локальная база знаний по геологической литературе. Сама ищет статьи в
интернете, разбирает их, складывает в базу и отвечает: поиском, чат-ботом на
Qwen3 со ссылками на статьи и графом знаний — в браузере и в Телеграме. Всё работает на одной машине, наружу ходит только за
самими статьями.

Все команды одинаковые для любого терминала и начинаются с `python georag.py`.
Полный список — `python georag.py help`.

---

## 1. Что поставить один раз

| Что | Зачем | Где взять |
|---|---|---|
| **Python 3.12** | на нём написан проект | python.org → Downloads. При установке отметить **«Add python.exe to PATH»** |
| **Docker Desktop** | в нём живёт база (PostgreSQL + pgvector) | docker.com → Docker Desktop |
| **Ollama** | языковая модель Qwen3: чат-бот, запросы к источникам, отбор статей, проверка разметки | ollama.com/download |
| Видеокарта NVIDIA | ускоряет разбор PDF и векторы в разы | необязательно: без неё всё работает, только медленнее |

После установки Ollama скачать модель (один раз, около 9 ГБ):

```
ollama pull qwen3:14b
```

Без Ollama работает всё, кроме чат-бота и проверки разметки моделью: поиск,
статьи и граф — да, отбор статей — по правилам.

---

## 2. Как открыть терминал в папке проекта

1. Откройте папку проекта в Проводнике.
2. Щёлкните по адресной строке сверху, сотрите путь, наберите `cmd` и нажмите Enter.

Откроется чёрное окно — командная строка, уже в папке проекта. Все команды
ниже набираются в нём. Подойдёт и любой другой терминал, если перейти в папку
проекта.

## 3. Первый запуск на новой машине

По порядку, один раз:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Первая команда создаёт окружение проекта, вторая ставит в него библиотеки —
это несколько минут и пара гигабайт.

Если есть видеокарта NVIDIA, поставить сборку с её поддержкой (для RTX 50-й
серии — cu128) и проверить:

```
.venv\Scripts\python -m pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -c "import torch; print(torch.cuda.is_available())"
```

Должно напечатать `True`.

Дальше — запустить Docker Desktop (значок кита должен перестать мигать) и:

```
python georag.py start
python georag.py init
python georag.py test
```

`start` поднимает базу, `init` создаёт в ней таблицы, `test` проверяет, что
код цел. В конце должно быть «Все проверки прошли». Проверки идут на выдуманных
примерах (щит, зоны, статьи «Т») — ваша база ими не трогается; подробный вывод —
`python georag.py test --verbose`.

Окружение `.venv` запускатель находит сам: набирать можно обычный `python`,
библиотеки всё равно возьмутся из `.venv`.

Желательно один раз указать свой e-mail — OpenAlex и Crossref тогда отвечают
ровнее. Он хранится в файле `mailto.txt` в папке проекта и в репозиторий не
попадает:

```
python -c "open('mailto.txt','w',encoding='utf-8').write('ваш@адрес')"
```

**Ключ OpenAlex — обязательно.** С 13 февраля 2026 года OpenAlex без ключа
отвечает на сотню запросов в день, дальше — ошибкой, и главный источник статей
молчит. Ключ бесплатный: завести учётную запись на openalex.org и скопировать
ключ со страницы openalex.org/settings/api. Сохранить один раз (файл тоже не
попадает в репозиторий):

```
python -c "open('openalex_key.txt','w',encoding='utf-8').write('ВАШ_КЛЮЧ')"
```

**Запросы — словами, а не вопросом.** Источники ищут по словам: вопрос «Какие
признаки использовались…» находит статьи про признаки чего угодно. Лучше
«гравиметрия прогноз оруденения» и отдельно по-английски «gravity mineral
prospectivity». Вопросительные слова программа и сама выбрасывает, а когда
работает Ollama, из вопроса запросы составляет Qwen3.

## 4. Инструменты

### Поиск статей в интернете

```
python georag.py add "выделение рудных узлов"
```

Берёт тему, составляет по ней запросы на русском и английском, ищет в
OpenAlex, Crossref и MDPI, отбирает то, что по теме, и разбирает найденные
PDF: разделы, таблицы, номера страниц. Сохраняются ссылка на статью и
разобранный текст — **сами PDF на диск не сохраняются**.

По всем темам сразу:

```
python georag.py all
```

Темы лежат в `config\topics.yaml` — это обычный текстовый файл, его можно править
Блокнотом. Темы по Анабарскому щиту — отдельным файлом:

```
python georag.py all --topics topics-anabar.yaml
```

Источники поиска — в `config\sources.yaml`, новый сайт добавляется туда же без правки
кода.

Полезные ключи: `--max-docs 10` — сколько статей разбирать за тему (по
умолчанию 5), `--no-llm` — отбирать без модели, если Ollama выключена.

### Убрать статьи не по теме

```
python georag.py clean
python georag.py clean --apply
```

Первая команда только показывает, что выглядит лишним, вторая переносит это
в `data\acquired\_отсев`. Ничего не удаляется. Следующий `python georag.py ingest`
убирает эти статьи и из базы знаний — из поиска, чат-бота и графа.

С темой в кавычках каждую статью ещё и читает Qwen3 — по тем же правилам, что при
добыче. Так убираются статьи, попавшие в базу по старым правилам отбора:

```
python georag.py clean "гравиметрические признаки в моделях перспективности"
python georag.py clean "гравиметрические признаки в моделях перспективности" --apply
python georag.py ingest
```

### Загрузить в базу

```
python georag.py ingest
```

Добытое режется на фрагменты, каждый переводится в вектор и ложится в базу.
Уже загруженное пропускается.

### Поиск, статьи и чат-бот — в браузере

```
python georag.py web
```

Откроется `http://localhost:8000`. Три вкладки:

- **Поиск** — фрагменты статей по запросу. Ищет двумя способами сразу — по
  смыслу и по точным словам; русский запрос находит и английские статьи.
- **Статьи** — что разобрано, с разбором каждой статьи по фрагментам.
- **Чат-бот** — вопрос своими словами, ответ Qwen3 только тем, что бот нашёл
  в базе, и ищет вместе с моделью: Qwen3 делит сложный вопрос на части,
  составляет запросы (по-русски и по-английски), читает найденное, берёт только
  подходящее и, если чего-то не хватает, ищет ещё. Потом пишет ответ только по
  отобранному; после каждого утверждения — номер фрагмента, щелчок по нему
  открывает фрагмент и статью. Нужно подробно или кратко — так и напишите в
  вопросе, настроек нет. На вопрос «что
  известно об Анабарском щите» (или о любом методе, процессе) ответ собирается
  из датасета — все факты из всех статей базы, а не несколько найденных кусков.
  Если в базе такой информации нет — статьи не показываются: бот пишет
  «По вашему запросу в базе знаний такой информации нет» и ниже отвечает из
  общих знаний модели, с пометкой, что это не из базы. Можно спрашивать
  вдогонку («а по ASTER?») — он помнит разговор.
  Вкладка «Граф связей» — **граф знаний**, как в Obsidian, с поиском узла: сущности из статей и сами
  статьи; стрелка — факт («зона — входит в — щит»). Щелчок по сущности — внизу
  все факты о ней с цитатами и статьями; щелчок по статье — о чём в ней факты.

Окно терминала при этом не закрывать: пока оно открыто, страница работает.
Остановить — Ctrl+C в нём.

Чат-боту нужна работающая Ollama с моделью `qwen3:14b`. Её состояние видно
вверху вкладки: зелёная точка — готов, рыжая — что не так и что сделать.

То же без браузера:

```
python georag.py search "гидротермальные изменения по данным ASTER"
python georag.py ask "как выделяют рудные узлы по линеаментам?"
```

### То же в Телеграме

Страница в браузере остаётся, бот — дополнительно. Он работает на вашем
компьютере: пока компьютер включён и бот запущен, ему можно писать с телефона
откуда угодно.

Один раз:

1. В Телеграме найти **@BotFather**, отправить ему `/newbot`, придумать имя и
   адрес бота (адрес кончается на `bot`). BotFather пришлёт токен — длинную
   строку вида `123456789:AA…`.
2. Сохранить токен в папке проекта:
   ```
   python -c "open('telegram_token.txt','w',encoding='utf-8').write('ТОКЕН')"
   ```
3. Запустить бота и написать ему в Телеграме что угодно — он ответит «Нет
   доступа. Ваш id: …». Этот номер сохранить (перезапуск не нужен):
   ```
   python -c "open('telegram_users.txt','a',encoding='utf-8').write('ВАШ_ID\n')"
   ```
   Так же добавляются коллеги — по одному id в строке. Остальным бот не отвечает.

   **Открыть бота всем** — строка `*` в `telegram_users.txt`: отвечает любому, без
   ограничений. Вопросы модель пишет по одному: кто спросил, пока она занята, видит
   своё место в очереди. Закрыть — удалить строку `*`, перезапуск не нужен.

   Бот запускается в одном окне: вторая копия на этом компьютере сама не стартует
   (две копии забирают одни и те же сообщения и отвечают по нескольку раз).

Запуск:

```
python georag.py web --tg
python georag.py tg
```

Первая — страница в браузере и бот сразу, в одном окне (модель векторов одна на
двоих, видеопамяти меньше). Вторая — только бот. Просто `python georag.py web` (без
`--tg`) бота **не** запускает. Бот работает, пока открыто это окно; входящие
сообщения видны в нём.

Бот молчит — проверить по шагам (база и модели для этого не нужны):

```
python georag.py tg --check
```

Скажет, принят ли токен и как называется ваш бот (писать нужно именно ему), кому
бот отвечает, кто уже писал боту и с каким id, не запущен ли бот в другом окне.

В боте всё — кнопками. Внизу экрана постоянное меню: **Поиск**, **Статьи**,
**Датасеты**, **Новый разговор**, **Помощь**. Любой другой текст —
вопрос чат-боту.

- **Под ответом** — номера фрагментов [1], [2]… (нажал — фрагмент целиком, со
  ссылкой на статью у издателя и кнопкой «Вся статья»), «Как искал» (части
  вопроса, запросы, что модель отобрала и что искала ещё), «Новый разговор».
  Пока бот пишет — «Остановить».
- **Поиск** — бот спросит, что искать; выдача листается кнопками «‹ Назад» /
  «Дальше ›», номер открывает фрагмент, «Спросить бота об этом» задаёт запрос
  чат-боту.
- **Статьи** — весь список с листанием; у статьи — авторы, журнал, ссылка и все
  её фрагменты по порядку.
- **Датасеты** — сущности, у которых больше всего фактов, кнопками; у каждой —
  факты о ней, «Таблица для Excel» (файл CSV) и «Спросить бота» (что известно).
  Любую другую — командой `/dataset название`.

Команды тоже работают: `/search запрос`, `/articles`, `/dataset Анабарский щит`,
`/f 2`, `/new`, `/stats` (что в базе и готова ли модель). Подробно или кратко —
пишется в самом вопросе.

Токен и список id — в `telegram_token.txt` и `telegram_users.txt`, в репозиторий они
не попадают.

### Граф знаний

```
python georag.py graph --limit 30
python georag.py graph
```

**Qwen3** читает фрагменты статей по одному и выписывает факты: «от — связь —
к» и дословную цитату. Например: «Билляхская зона — входит в — Анабарский щит».
Сущности — как их назвала статья (место, метод, процесс — неважно), связь —
словами статьи. Первая команда — проба на 30 фрагментах, вторая — все новые.
Около 4–5 секунд на фрагмент; прервать можно Ctrl+C, та же команда продолжит с
того же места. Нужна Ollama с `qwen3:14b`.

Каждый факт **проверяет код**: цитата должна найтись в статье дословно, а в
цитате — оба конца факта. Не прошло проверку — в граф не попадает. Что
получилось и почему код отбрасывал остальное:

```
python georag.py graph --new
```

Правила для модели — `config\graph-rules.txt`, правятся Блокнотом. После правки —
`python georag.py graph --redo` (всё заново).

### Словарь синонимов

Одно и то же статьи пишут по-разному: «Donetsk basin», «Донбасс». Словарь
`config\synonyms.yaml` сводит такие написания к одному имени:

```
имена:
  Донецкий бассейн: [Donetsk basin, Донбасс, Donbass]
```

Падеж и число не важны — «Донецкого бассейна» узнаётся само. Чего в словаре
нет, в граф идёт как написала модель. Правка действует сразу, модель заново
проходить не нужно.

Пополнять словарь помогает модель, решаете вы:

```
python georag.py synonyms
```

Модель находит похожие имена и решает, одно ли это. Предложения — в файле
`config\synonyms-предложения.yaml`: откройте Блокнотом, нужные строки
перенесите в `config\synonyms.yaml`, ошибочные — просто не переносите.

### Датасеты

```
python georag.py dataset
python georag.py dataset "Анабарский щит"
```

Первая — у чего больше всего фактов. Вторая — все факты об Анабарском щите
(вместе с тем, что в него входит) и файл `data\datasets\датасет-Анабарский щит.csv`
для Excel. Датасет есть у любой сущности — у места, метода, процесса. На графе в
браузере — щелчок по узлу. Заранее датасеты не создаются и нигде не хранятся:
каждый собирается из фактов, когда его открывают, поэтому после нового `graph`
новые датасеты появляются сами.

### Оценка: насколько хорошо ищет и отвечает

```
python georag.py eval
python georag.py eval --only-search
```

Прогоняет около тридцати вопросов из `config\eval-questions.yaml` и пишет отчёт
в `logs\eval-<дата>.md`: что нашлось, по базе ли ответ, не отписка ли, у скольких
утверждений есть ссылка на статью. Каждый прогон сравнивается с прошлым.
Без Ollama — второй вариант, только поиск.

Чтобы на все вопросы оценки в базе были статьи:

```
python georag.py all --topics topics-check.yaml
python georag.py ingest
python georag.py graph
```

## 5. Обычный порядок работы

```
python georag.py start
python georag.py all
python georag.py clean
python georag.py ingest
python georag.py graph
python georag.py eval
python georag.py web
```

Добыть → посмотреть лишнее → загрузить → граф → оценить → искать и спрашивать.

### После обновления кода до новой версии — один раз

```
python georag.py init
python georag.py graph --redo
python georag.py synonyms
```

`init` доводит таблицы до новой схемы. `graph --redo` — граф по-новому: Qwen3
заново проходит все фрагменты и выписывает факты (4–5 секунд на фрагмент, можно
прерывать Ctrl+C и продолжать той же командой). `synonyms` — предложения в
словарь синонимов: просмотреть и перенести нужное в `config\synonyms.yaml`.

## 6. Чтобы база пополнялась сама

```
python georag.py schedule
```

Один раз — и каждую ночь в 03:00 Windows сам запустит добычу по всем темам,
загрузку в базу и граф (до 300 новых фрагментов за ночь). Логи — в папке `logs`, старше месяца удаляются.
Компьютер в это время должен быть включён; если он спал, прогон случится,
когда проснётся.

| Команда | Что делает |
|---|---|
| `python georag.py schedule --at 01:30` | другое время |
| `python georag.py nightly` | сделать ночной прогон прямо сейчас |
| `python georag.py unschedule` | убрать ночной прогон |

## 7. Если что-то не работает

| Что видите | Что делать |
|---|---|
| `python` не является внутренней или внешней командой | Python не поставлен или без галочки «Add to PATH» — переустановить с галочкой |
| Не найдено окружение .venv | вы не в папке проекта, или раздел 3 не сделан |
| Docker не найден / не отвечает | запустить Docker Desktop, дождаться, пока кит перестанет мигать |
| База недоступна | `python georag.py start`, потом `python georag.py status` |
| Контейнер в статусе Restarting | `docker compose logs db` — там причина |
| Чат-бот: «Ollama не отвечает» | запустить Ollama (значок ламы у часов) или переустановить с ollama.com/download |
| Чат-бот: «Модель qwen3:14b не скачана» | `ollama pull qwen3:14b` |
| Телеграм-бот молчит | запущен ли `python georag.py web --tg` (именно с `--tg`) и открыто ли окно; дальше — `python georag.py tg --check` |
| Чат-бот отвечает «в базе знаний об этом нет» | в базе правда нет статей по теме — добавить: `python georag.py add "тема"` |
| Ollama не отвечает | `ollama list`; если пусто — `ollama pull qwen3:14b` |
| `llama-server binary not found` | установка Ollama повреждена — переустановить поверх с ollama.com/download, модели сохранятся |
| Статьи не скачиваются (403) | защита издателя или платный доступ: остаётся ссылка, текст взять нельзя |
| На графе лишняя сущность или связь | `python georag.py graph --new` — что нашла модель; поправить `config\graph-rules.txt` и `graph --redo` |
| Одно и то же на графе двумя узлами | дописать синоним в `config\synonyms.yaml` (или `python georag.py synonyms`) |
| «Словарь синонимов: …» при запуске | ошибка в `config\synonyms.yaml` — синонимы в [квадратных скобках], через запятую; сохранять в UTF-8 |

**Никогда** не набирайте `docker compose down -v`: это удаляет базу целиком.

## 8. Что где лежит

```
georag.py           ← вход для всех команд
ЗАПУСК.md           ← этот файл
README.md           ← коротко о проекте
config\             ← всё, что правится руками
   topics.yaml          темы поиска статей
   topics-anabar.yaml   темы по Анабарскому щиту
   topics-check.yaml    темы под вопросы оценки
   eval-questions.yaml  вопросы для оценки (python georag.py eval)
   graph-rules.txt      правила для Qwen3: как выписывать факты
   sources.yaml         где искать статьи
   synonyms.yaml        словарь синонимов для графа
docs\               ← КОМАНДЫ.md — все ключи; УСТРОЙСТВО.md — как устроено
georag\             ← сам код
   acquire\            поиск и скачивание статей
   parse\              разбор PDF
   index\              база, векторы, поиск
   graph\              граф знаний: факты, синонимы, датасеты
   chat\               чат-бот
   web\                страница в браузере
tests\              ← проверки кода, эталоны разбора и тестовый корпус
data\               ← добытое: ссылки, тексты, фрагменты (в git не идёт)
logs\               ← логи прогонов (в git не идёт)
docker-compose.yml  ← описание базы
requirements.txt    ← список библиотек
```
