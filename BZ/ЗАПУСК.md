# ГеоRAG — как запустить

Локальная база знаний по геологической литературе. Сама ищет статьи в
интернете, разбирает их, складывает в базу, размечает по понятиям и отвечает
на поиск — в браузере или по запросу от базы данных проекта. Всё работает на
одной машине, наружу ходит только за самими статьями.

Все команды одинаковые для любого терминала и начинаются с `python georag.py`.
Полный список — `python georag.py help`.

---

## 1. Что поставить один раз

| Что | Зачем | Где взять |
|---|---|---|
| **Python 3.12** | на нём написан проект | python.org → Downloads. При установке отметить **«Add python.exe to PATH»** |
| **Docker Desktop** | в нём живёт база (PostgreSQL + pgvector) | docker.com → Docker Desktop |
| **Ollama** | языковая модель: запросы к источникам, отбор статей, проверка разметки | ollama.com/download |
| Видеокарта NVIDIA | ускоряет разбор PDF и векторы в разы | необязательно: без неё всё работает, только медленнее |

После установки Ollama скачать модель (один раз, около 9 ГБ):

```
ollama pull qwen3:14b
```

Без Ollama проект тоже работает: отбор статей идёт по правилам, не работает
только проверка разметки моделью.

---

## 2. Как открыть терминал в папке проекта

1. Откройте папку проекта в Проводнике.
2. Щёлкните по адресной строке сверху, сотрите путь, наберите `cmd` и нажмите Enter.

Откроется чёрное окно — командная строка, уже в папке проекта. Все команды
ниже набираются в нём. Подойдёт и любой другой терминал, если перейти в папку
проекта.

## 3. Первый запуск на новой машине

По порядку, один раз:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Первая команда создаёт окружение проекта, вторая ставит в него библиотеки —
это несколько минут и пара гигабайт.

Если есть видеокарта NVIDIA, поставить сборку с её поддержкой (для RTX 50-й
серии — cu128) и проверить:

```
.venv\Scripts\python -m pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -c "import torch; print(torch.cuda.is_available())"
```

Должно напечатать `True`.

Дальше — запустить Docker Desktop (значок кита должен перестать мигать) и:

```
python georag.py start
python georag.py init
python georag.py test
```

`start` поднимает базу, `init` создаёт в ней таблицы, `test` проверяет, что
код цел. В конце должно быть «Все проверки прошли».

Окружение `.venv` запускатель находит сам: набирать можно обычный `python`,
библиотеки всё равно возьмутся из `.venv`.

Желательно один раз указать свой e-mail — OpenAlex и Crossref тогда отвечают
ровнее. Он хранится в файле `mailto.txt` в папке проекта и в репозиторий не
попадает:

```
python -c "open('mailto.txt','w',encoding='utf-8').write('ваш@адрес')"
```

## 4. Инструменты

### Поиск статей в интернете

```
python georag.py add "выделение рудных узлов"
```

Берёт тему, составляет по ней запросы на русском и английском, ищет в
OpenAlex, Crossref и MDPI, отбирает то, что по теме, и разбирает найденные
PDF: разделы, таблицы, номера страниц. Сохраняются ссылка на статью и
разобранный текст — **сами PDF на диск не сохраняются**.

По всем темам сразу:

```
python georag.py all
```

Темы лежат в `topics.yaml` — это обычный текстовый файл, его можно править
Блокнотом. Темы по Анабарскому щиту — отдельным файлом:

```
python georag.py all --topics topics-anabar.yaml
```

Источники поиска — в `sources.yaml`, новый сайт добавляется туда же без правки
кода.

Полезные ключи: `--max-docs 10` — сколько статей разбирать за тему (по
умолчанию 5), `--no-llm` — отбирать без модели, если Ollama выключена.

### Убрать статьи не по теме

```
python georag.py clean
python georag.py clean --apply
```

Первая команда только показывает, что выглядит лишним, вторая переносит это
в `data\acquired\_отсев`. Ничего не удаляется.

### Загрузить в базу

```
python georag.py ingest
```

Добытое режется на фрагменты, каждый переводится в вектор и ложится в базу.
Уже загруженное пропускается.

### Поиск по базе

```
python georag.py search "гидротермальные изменения по данным ASTER"
```

Ищет двумя способами сразу — по смыслу и по точным словам — и показывает
фрагменты со ссылкой на статью и страницу. Русский запрос находит и
английские статьи.

Удобнее в браузере:

```
python georag.py web
```

Откроется `http://localhost:8000`. Вкладки:

- **Поиск** — то же, что `search`, но отвечает мгновенно;
- **Статьи в базе** — что разобрано, с разбором каждой статьи по фрагментам;
- **Понятия** — фрагменты статей по каждому понятию словаря, с цитатами;
- **Граф связей** — вся база одной сетью, как граф в Obsidian: статьи, понятия,
  территории, методы, объекты и полезные ископаемые. Переключатель «Схема» —
  то же только по словарю, в три колонки.

Окно терминала при этом не закрывать: пока оно открыто, страница работает.
Остановить — Ctrl+C в нём.

### Понятия и граф связей

```
python georag.py graph
```

Размечает все фрагменты по словарю `vocabulary.yaml`: какие фрагменты
описывают какие понятия (структурный контроль, гидротермальные изменения и
другие), какие территории и методы в них названы. У каждой найденной связи —
дословная цитата из статьи. Модель для этого не нужна.

Посмотреть результат:

```
python georag.py concepts
python georag.py concept "гидротермальные изменения"
python georag.py concept "структурный контроль" --territory "Анабарский щит"
```

Или во вкладках «Понятия» и «Граф связей» в браузере.

Проверка моделью — она читает каждый найденный фрагмент и подтверждает или
отклоняет его:

```
python georag.py verify --limit 50
python georag.py verify
```

Первая — пробный прогон на 50 фрагментах, вторая — всё остальное. Две-три
секунды на фрагмент; можно прервать Ctrl+C и продолжить той же командой.
Нужна работающая Ollama.

Словарь `vocabulary.yaml` правится Блокнотом (сохранять в UTF-8). Понятия в нём —
копия справочника базы данных проекта, их коды менять нельзя. Синонимы,
территории и методы — можно. После правки — снова `python georag.py graph`.

## 6. Мост с базой данных проекта

База данных проекта (`gis_au_u`, репозиторий GIS-agent-db) хранит признаки и их
паспорта. В паспорте есть поле «Обоснование», и сейчас в нём написано
«публикация не привязана, база знаний в разработке». Мост заполняет его
литературой отсюда.

Общее у двух баз — **понятия**: у них справочник `kb.concept`, у нас — тот же
список в `vocabulary.yaml`, коды совпадают. Цепочка такая:

```
признак (у них) → понятие (общее) → статьи с цитатами (у нас)
```

Их скрипт берёт каждый черновик паспорта, по своей таблице связей находит его
понятие и спрашивает у нас: что в статьях написано про это понятие по нашей
территории и тем же методом (для признаков из ASTER — по ASTER). Ответ ложится
в обоснование паспорта черновиком, подтверждает человек в их панели.

### Что запустить

**Здесь, на машине с базой знаний:**

```
python georag.py graph
python georag.py serve
```

`serve` — тот же сервер, что `web`, только без браузера. Окно не закрывать,
пока мостом пользуются.

**На машине с базой данных, в папке GIS-agent-db** (один раз — накатить
миграции `011` и `012` из патча, как описано в их `db/README.md`):

```
python scripts/db_kb_evidence.py --сухой
python scripts/db_kb_evidence.py
```

Первая команда показывает, что пришло бы, и ничего не пишет. Вторая
записывает: статьи — в `kb.publication`, цитаты — в `kb.citation`, блок
литературы — в конец обоснования черновиков паспортов. Подтверждённые
паспорта не трогаются. Повторный запуск блок заменяет, а не дописывает второй.

Посмотреть — их панель подтверждений `python -m gisdb.panel`, карточка
паспорта, поле «Обоснование».

### Если базы на разных компьютерах

Страница базы знаний слушает только свой компьютер, поэтому с другого к ней
ходят через SSH-туннель.

На **этом** компьютере один раз включить сервер SSH: Параметры → Система →
Дополнительные компоненты → Добавить компонент → «Сервер OpenSSH». Затем в
«Службах» Windows запустить «OpenSSH SSH Server» и поставить тип запуска
«Автоматически».

На **компьютере с базой данных** поднять туннель и не закрывать окно:

```
ssh -N -L 8000:127.0.0.1:8000 Janfik@АДРЕС-ЭТОГО-КОМПЬЮТЕРА
```

После этого адрес `http://localhost:8000` на той машине ведёт сюда, и скрипт
моста работает без изменений. Если базы на одном компьютере — туннель не
нужен.

## 7. Чтобы база пополнялась сама

```
python georag.py schedule
```

Один раз — и каждую ночь в 03:00 Windows сам запустит добычу по всем темам,
загрузку в базу и разметку. Логи — в папке `logs`, старше месяца удаляются.
Компьютер в это время должен быть включён; если он спал, прогон случится,
когда проснётся.

| Команда | Что делает |
|---|---|
| `python georag.py schedule --at 01:30` | другое время |
| `python georag.py nightly` | сделать ночной прогон прямо сейчас |
| `python georag.py unschedule` | убрать ночной прогон |

## 8. Если что-то не работает

| Что видите | Что делать |
|---|---|
| `python` не является внутренней или внешней командой | Python не поставлен или без галочки «Add to PATH» — переустановить с галочкой |
| Не найдено окружение .venv | вы не в папке проекта, или раздел 3 не сделан |
| Docker не найден / не отвечает | запустить Docker Desktop, дождаться, пока кит перестанет мигать |
| База недоступна | `python georag.py start`, потом `python georag.py status` |
| Контейнер в статусе Restarting | `docker compose logs db` — там причина |
| Ollama не отвечает | `ollama list`; если пусто — `ollama pull qwen3:14b` |
| `llama-server binary not found` | установка Ollama повреждена — переустановить поверх с ollama.com/download, модели сохранятся |
| Скрипт моста: «база знаний не отвечает» | здесь не запущен `python georag.py serve`, или на той машине не поднят туннель |
| Статьи не скачиваются (403) | защита издателя или платный доступ: остаётся ссылка, текст взять нельзя |
| Во вкладке «Понятия» почти все статьи у каждого понятия | пороги мягкие — см. раздел 3б в `КОМАНДЫ.md` |

**Никогда** не набирайте `docker compose down -v`: это удаляет базу целиком.

## 9. Что где лежит

```
georag.py           ← вход для всех команд
ЗАПУСК.md           ← этот файл
КОМАНДЫ.md          ← все ключи и тонкие настройки
topics.yaml         ← темы поиска статей
sources.yaml        ← где искать статьи
vocabulary.yaml     ← словарь: понятия, территории, методы
docker-compose.yml  ← описание базы
requirements.txt    ← список библиотек
georag\             ← сам код
data\acquired\      ← добытое: ссылки, тексты, фрагменты
logs\               ← логи прогонов
```
