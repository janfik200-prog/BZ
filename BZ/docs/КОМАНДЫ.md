# ГеоRAG — все команды и настройки

Как поставить и запустить — в `ЗАПУСК.md` в корне проекта. Здесь справочник: короткие команды,
полные команды со всеми ключами и тонкие настройки.

Всё набирается в терминале, открытом в папке проекта. Короткие команды
начинаются с `python georag.py`, полные — с `.venv\Scripts\python -m …`:
ими пользуются, когда нужен ключ, которого нет у короткой.

---

## 1. Короткие команды

| Что делаем | Команда |
|---|---|
| Поднять базу | `python georag.py start` |
| Что работает | `python georag.py status` |
| Добыть по одной теме | `python georag.py add "выделение рудных узлов"` |
| Сохранить ключ OpenAlex (один раз, обязательно) | `python -c "open('openalex_key.txt','w').write('КЛЮЧ')"` |
| Добыть по всем темам | `python georag.py all` |
| По темам из другого файла | `python georag.py all --topics topics-anabar.yaml` |
| Посмотреть, что не по теме | `python georag.py clean` |
| Убрать не по теме | `python georag.py clean --apply` |
| То же, и Qwen3 проверяет каждую статью по теме | `python georag.py clean "тема" --apply` |
| Загрузить в базу | `python georag.py ingest` |
| То же, векторы через Ollama | `python georag.py ingest --ollama` |
| Убрать служебный текст из уже загруженной базы (благодарности, колонтитулы, e-mail) | `python georag.py tidy` |
| Поискать | `python georag.py search "рудные узлы"` |
| Спросить чат-бота | `python georag.py ask "как выделяют рудные узлы?"` |
| Подробно или кратко — словами в вопросе | `python georag.py ask "кратко: как выделяют рудные узлы?"` |
| Датасеты — у чего больше всего фактов | `python georag.py dataset` |
| Датасет любой сущности, таблица для Excel | `python georag.py dataset "Анабарский щит"` |
| Оценить базу и чат-бота | `python georag.py eval` |
| Оценить только поиск (без Ollama) | `python georag.py eval --only-search` |
| Добрать статьи под вопросы оценки | `python georag.py all --topics topics-check.yaml` |
| Граф: Qwen3 выписывает факты из статей | `python georag.py graph` |
| Проба графа на 30 фрагментах | `python georag.py graph --limit 30` |
| Вопросы оценки из фактов графа | `python georag.py questions` → `eval --questions config/eval-graph.yaml` |
| Где не хватает статей → темы добычи | `python georag.py gaps` → `all --topics topics-graph.yaml` |
| Граф заново (после правки правил) | `python georag.py graph --redo` |
| Что нашла модель и где ошибалась | `python georag.py graph --new` |
| Перепроверить готовый граф новыми правилами кода (без модели) | `python georag.py graph --recheck` |
| Подтвердить факты вопросами по цитате (идёт и само после `graph`) | `python georag.py graph --confirm` |
| Предложения в словарь синонимов | `python georag.py synonyms` |
| Поиск, статьи, чат-бот и граф в браузере | `python georag.py web` |
| То же + Телеграм-бот | `python georag.py web --tg` |
| Только Телеграм-бот | `python georag.py tg` |
| Бот молчит — проверить токен, доступ, кто писал | `python georag.py tg --check` |
| Сервер без браузера (только адреса /api) | `python georag.py serve` |
| Что в базе | `python georag.py stats` |
| Ночной прогон каждую ночь | `python georag.py schedule` |
| Ночной прогон сейчас | `python georag.py nightly` |
| Убрать ночной прогон | `python georag.py unschedule` |
| Проверить код | `python georag.py test` |
| Остановить базу | `python georag.py stop` |

Порядок всегда один: **добыть → почистить → загрузить → граф → искать и спрашивать.**

## 2. Добыча статей — все ключи

```
.venv\Scripts\python -m georag.acquire.cli "выделение рудных узлов" --max-docs 5 --no-ocr --device cuda --mailto ваш@адрес --model qwen3:14b
```

По всем темам сразу — вместо темы в кавычках `--topics config/topics.yaml`.

| Ключ | Зачем |
|---|---|
| `--topics config/topics.yaml` | взять список тем из файла вместо одной темы |
| `--max-docs 5` | сколько статей разбирать за тему |
| `--no-ocr` | не распознавать картинки — быстрее в разы, для обычных статей не нужно |
| `--device cuda` | считать на видеокарте |
| `--mailto ...` | вежливый режим OpenAlex и Crossref: ответы стабильнее |
| `--model qwen3:14b` | какая модель в Ollama отбирает статьи |
| `--no-llm` | не спрашивать модель, решать эвристикой (когда Ollama выключена) |
| `--dry-run` | только поиск и отбор, без разбора — быстрая проверка |
| `--force` | не пропускать статьи, которые уже видели |
| `--tables fast` | быстрый разбор таблиц вместо точного |
| `--per-query 25` | сколько результатов брать из каждого источника |

Только запросы, без поиска — посмотреть, что модель придумала по теме:

```
.venv\Scripts\python -m georag.acquire.cli "рудные узлы" --queries-only
.venv\Scripts\python -m georag.acquire.cli --topics config/topics.yaml --queries-only --save-queries queries.yaml
```

Файл `queries.yaml` можно править руками, а потом искать по нему, не
спрашивая модель каждый раз:

```
.venv\Scripts\python -m georag.acquire.cli --topics config/topics.yaml --queries-file queries.yaml
```

## 3. Поиск — все ключи

```
.venv\Scripts\python -m georag.index.cli search "гидротермальные изменения ASTER" --limit 10 --per-doc 2 --year-from 2015
```

| Ключ | Зачем |
|---|---|
| `--limit 10` | сколько результатов показать |
| `--per-doc 2` | не больше N кусков одной статьи (0 — без ограничения) |
| `--year-from 2015` | только статьи не старше указанного года |
| `--source openalex` | искать только по одному источнику |
| `--candidates 50` | сколько кандидатов брать из каждого поиска до объединения |
| `--min-similarity 0.45` | отсечь непохожее: 0.45 — обычно, 0.55 — строго, 0 — показывать всё |
| `--require-words` | только куски, где буквально есть все слова запроса |
| `--embedder ollama` | считать вектор запроса через Ollama, а не на видеокарте |

Векторный поиск всегда возвращает ближайшее — даже когда подходящего в базе
нет. Поэтому есть порог `--min-similarity`. У BGE-M3 текст про то же самое
даёт похожесть примерно от 0.6, случайный сосед — около 0.3–0.45. Куски, где
буквально есть все слова запроса, проходят порог всегда.

У каждого результата написано, **кто его нашёл**: «вектор» — по смыслу,
«текст» — по точным словам, «оба» — согласились оба способа. «Оба» — самый
надёжный признак.

## 3а. Страница в браузере

```
python georag.py web
```

`http://localhost:8000`, три вкладки: **Поиск**, **Статьи**, **Чат-бот** (под
ним — граф связей). Модель векторов грузится один раз при запуске, поэтому
поиск отвечает мгновенно. Остановить — Ctrl+C в том же окне. Страница слушает
только этот компьютер: из сети к ней не подключиться.

Другой порт — `.venv\Scripts\python -m georag.web.server --port 9000`.
Другая модель для чат-бота — `--model qwen3:8b` (она должна быть скачана в Ollama).

### Чат-бот

Как он отвечает, по шагам:

1. Qwen3 разбирает вопрос. Составной («какие признаки и какими методами их
   выделяют») делится на части, до трёх; на каждую — 3 поисковых запроса,
   по-русски и по-английски. Ищется и сам вопрос. Вопрос вдогонку
   («а по ASTER?») модель дописывает до самостоятельного — с предметом из прошлого.
2. **Поиск вместе с моделью.** Поиск приносит кандидатов с запасом (до 16 на
   вопрос, по 8 на часть составного, мягкий порог), Qwen3 **читает всех** пачками
   **и берёт только подходящие** —
   похожее по словам, но о другом, отбрасывает. Если чего-то не хватает, модель
   сама составляет новые запросы и ищет ещё — до трёх кругов. Для ответа — до 8
   фрагментов, не больше 3 из одной статьи; у каждой части вопроса свои места.
   Под ответом видно: сколько фрагментов прочла модель, сколько было кругов, чего
   не хватало и что искалось ещё. Если Ollama не отвечает — фрагменты берутся по
   близости, как в обычном поиске.
   - **«Что известно о …»**, «перечисли всё про …» — ответ собирается из
     датасета: фрагмент [1] — все факты о предмете вопроса из графа знаний,
     за ним — фрагменты, откуда взяты цитаты главных фактов. Предмет может быть
     любым — место, метод, процесс. Нужен построенный граф (`python georag.py graph`).
3. **Нашлось** — Qwen3 пишет ответ только по этим фрагментам и после каждого
   утверждения ставит номер фрагмента. Номера сверяются: ссылка на фрагмент,
   которого модели не давали, зачёркивается. Под ответом — источники, что
   искал бот и сколько утверждений подкреплены номером фрагмента.
4. **Не нашлось** (или модель прочла фрагменты, а ответа в них нет) — статьи
   не показываются. Бот пишет: «По вашему запросу в базе знаний такой
   информации нет» — и ниже отвечает из общих знаний модели, с пометкой
   «ответ модели, не из базы знаний». В таком ответе нет ссылок на статьи.
   Если вопрос вообще не о геологии («как испечь хлеб?») — только короткий отказ.

Размышления вслух у Qwen3 выключены — ответ в разы быстрее.

**Настроек у ответа нет.** Нужно подробно, кратко, списком, таблицей — так и
напишите в вопросе: «подробно: какие признаки…», «кратко — чем выделяют узлы?».
Не сказали — ответ по существу: вывод и главное списком.

Числа — в начале файла `georag\chat\answer.py` (сколько запросов и фрагментов,
сколько кругов поиска, пороги, сколько прошлых реплик помнить, правила для модели).

Из терминала — один вопрос, без разговора:

```
python georag.py ask "какие признаки гидротермальных изменений видны на ASTER?"
```

## 3б. Граф знаний и словарь синонимов

### Как строится

```
python georag.py graph --limit 30     проба: 30 фрагментов
python georag.py graph                все новые фрагменты
python georag.py graph --redo         всё заново — после правки правил
python georag.py graph --new          что нашла модель и почему код отбрасывал
```

Qwen3 читает фрагменты статей по одному и выписывает **факты**: «от — связь — к»
и дословную цитату. «Билляхская зона — входит в — Анабарский щит». Сущности —
как их назвала статья (место, метод, процесс — без разделения на виды); связь —
словами статьи, по-русски, 1–4 слова. Правила для модели —
`config\graph-rules.txt`, правятся Блокнотом (сохранять в UTF-8); после правки —
`graph --redo`.

Каждый факт **проверяет код**: цитата должна найтись во фрагменте дословно, а в
цитате — оба конца факта (с любыми окончаниями). Не прошло — в граф не
попадает. Выдуманные названия и названия, дописанные «по смыслу», так
отсекаются. `graph --new` показывает, какие сущности и связи получились и
почему код отбрасывал остальное.

4–5 секунд на фрагмент на видеокарте. Прервать можно в любой момент (Ctrl+C) —
та же команда продолжит с того же места. Нужна Ollama с `qwen3:14b`.

### Словарь синонимов

`config\synonyms.yaml` — разные написания одного и того же сводятся к одному
имени:

```
имена:
  Донецкий бассейн: [Donetsk basin, Донбасс, Donbass]
связи:
  приурочено к: [приурочен к, associated with]
```

Первое — как показывать, в скобках — как ещё пишут. Падеж и число не важны:
«Донецкого бассейна» узнаётся само. Чего в словаре нет, в граф идёт как написала
модель. Сюда — только настоящие синонимы (перевод, сокращение, другое
написание); «random forest» и «машинное обучение» — не синонимы, это факт.

Правка действует **сразу**: модель заново проходить не нужно, страницу — просто
обновить, бота перезапускать не надо.

Пополнять словарь помогает модель:

```
python georag.py synonyms
```

Она находит похожие имена (векторы BGE-M3) и по парам решает, одно ли это.
Предложения — в `config\synonyms-предложения.yaml`, в том же виде, что словарь.
Откройте Блокнотом, нужные строки перенесите в `synonyms.yaml`, ошибочные — просто
не переносите. Сама модель словарь не правит. Строже или мягче —
`.venv\Scripts\python -m georag.graph.cli synonyms --threshold 0.85` (обычно 0.8;
выше — меньше предложений).

### Датасеты

```
python georag.py dataset                     у чего больше всего фактов
python georag.py dataset "Анабарский щит"    все факты о нём, файл CSV для Excel
```

Датасет есть у любой сущности: все факты о ней — с чем и как связана, в скольких
статьях, цитата и статья. Факты о том, что в неё **входит** (по фактам «входит
в»), тоже попадают: датасет щита включает его зоны. Таблица кладётся в
`data\datasets`. То же — в карточке узла на графе и в Телеграме (/dataset).

Готовых датасетов нет: каждый собирается из фактов в момент, когда его
открывают. Новый `graph` — новые сущности и их датасеты появляются сами.

### Граф на странице

Под чат-ботом — все факты одной сетью, как граф в Obsidian: сущности (синие) и
статьи (серые). Стрелка — факт, по направлению связи; тонкая линия — от статьи к
сущностям, о которых в ней факты. Колесо — масштаб, тянуть фон — сдвиг. Щелчок
по сущности — её датасет: строки фактов, нажатие на строку — цитата и кнопка
статьи; «Спросить чат-бота» — вопрос «что известно о …». Щелчок по статье — о
чём в ней факты и «Разбор статьи целиком».

### Адреса

Сервер — тот же, что открывает `python georag.py web` (`serve` — без браузера).

| Адрес | Что отдаёт |
|---|---|
| `GET /api/network` | сеть: сущности, статьи, факты с цитатами |
| `GET /api/datasets` | у каких сущностей больше всего фактов |
| `GET /api/dataset?name=Анабарский щит` | датасет сущности; `&format=csv` — таблицей; POST — то же JSON в теле |

С другой машины — только через SSH-туннель.

## 4. База в Docker

```
docker compose up -d          # поднять (первый раз — создаёт)
docker compose stop           # остановить, данные остаются
docker compose ps             # что сейчас работает
docker compose logs db        # что пишет база, если не поднимается
```

**Никогда:** `docker compose down -v` — удаляет том с базой, и всё придётся
загружать заново.

Перезагрузить всё в базу с нуля, не трогая добытые статьи:

```
python georag.py ingest --force
```

Граф при этом сохраняется: факты стираются только у фрагментов, чей текст поменялся,
и следующий `python georag.py graph` пройдёт их заново.

## 5. Ollama

Ollama отвечает за языковую работу: запросы к источникам, отбор статей,
граф знаний (`graph`, `synonyms`). Векторы считаются на видеокарте без неё.

```
ollama list                   # какие модели скачаны
ollama pull qwen3:14b         # основная модель
ollama pull bge-m3            # нужна, только если считать векторы через Ollama (--ollama)
ollama ps                     # что сейчас в памяти
ollama stop qwen3:14b         # выгрузить из видеопамяти
```

Модель выгружается сама примерно через пять минут простоя.

Модель и адрес Ollama — в `georag/llm.py` (адрес можно задать переменной
`GEORAG_OLLAMA`); адрес почты и имя ночной задачи — в начале `georag.py`.

## 6. Проверка и логи

### Оценка базы и чат-бота

```
python georag.py eval                  поиск и ответы по вопросам config\eval-questions.yaml
python georag.py eval --only-search    только поиск — если Ollama не работает
python georag.py eval --only s01,t01   отдельные вопросы
```

Отчёт — `logs\eval-<дата>.md` (открывается Блокнотом) и `.json`. В начале отчёта
итог и сравнение с прошлым прогоном, дальше таблица по вопросам и разбор того,
что не прошло: не нашлось, нет ключевого, короткий ответ, мало ссылок, ответил
по базе на вопрос не по теме. Раздел «Где базе не хватает статей» — по каким вопросам
добрать темами `topics-check.yaml`.

Свои вопросы добавляются в `config\eval-questions.yaml` — формат описан в начале
файла. Лучше всего работают вопросы, ответ на которые вы сами знаете по статьям.

### Код и логи

```
python georag.py test
python georag.py test --verbose
.venv\Scripts\python -c "import torch; print(torch.cuda.is_available())"
nvidia-smi
```

`test` проверяет код на выдуманных примерах (щит, зоны, статьи «Т», «d1») — база,
статьи и граф не трогаются, Ollama не нужна. На экран — строка на каждую часть;
`--verbose` — все проверки подряд, это для разбора, а не данные вашей базы.

Логи и отчёты — обычные текстовые файлы, открываются Блокнотом:

- `logs\run-*.txt` — ночные прогоны;
- `logs\acquire-*.jsonl` — по шагам, что происходило в добыче;
- `data\acquired\acquire-report-*.json` — итог прогона добычи;
- `data\acquired\index.jsonl` — что уже добыто (по нему пропускаются повторы);
- `data\acquired\_отсев\` — то, что убрал `clean`.

Тестовый корпус для проверки разбора PDF (единственное место, где PDF
скачиваются на диск, — для сверки с эталонами):

```
.venv\Scripts\python tests\corpus\download_corpus.py
.venv\Scripts\python -m georag.parse.cli --input data\pdf --device cuda
```
