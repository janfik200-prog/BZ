# ГеоRAG — все команды и настройки

Как поставить и запустить — в `ЗАПУСК.md`. Здесь справочник: короткие команды,
полные команды со всеми ключами и тонкие настройки.

Всё набирается в терминале, открытом в папке проекта. Короткие команды
начинаются с `python georag.py`, полные — с `.venv\Scripts\python -m …`:
ими пользуются, когда нужен ключ, которого нет у короткой.

---

## 1. Короткие команды

| Что делаем | Команда |
|---|---|
| Поднять базу | `python georag.py start` |
| Что работает | `python georag.py status` |
| Добыть по одной теме | `python georag.py add "выделение рудных узлов"` |
| Добыть по всем темам | `python georag.py all` |
| По темам из другого файла | `python georag.py all --topics topics-anabar.yaml` |
| Посмотреть, что не по теме | `python georag.py clean` |
| Убрать не по теме | `python georag.py clean --apply` |
| Загрузить в базу | `python georag.py ingest` |
| То же, векторы через Ollama | `python georag.py ingest --ollama` |
| Поискать | `python georag.py search "рудные узлы"` |
| Разметить по словарю | `python georag.py graph` |
| То же + проверка моделью | `python georag.py graph --llm` |
| Проверка моделью с места остановки | `python georag.py verify` |
| Пробная проверка | `python georag.py verify --limit 50` |
| Что найдено по понятиям | `python georag.py concepts` |
| Фрагменты по понятию | `python georag.py concept "магматизм"` |
| С отбором | `python georag.py concept "магматизм" --territory "Анабарский щит" --method ASTER` |
| Всё в браузере | `python georag.py web` |
| Сервер для базы данных проекта | `python georag.py serve` |
| Что в базе | `python georag.py stats` |
| Ночной прогон каждую ночь | `python georag.py schedule` |
| Ночной прогон сейчас | `python georag.py nightly` |
| Убрать ночной прогон | `python georag.py unschedule` |
| Проверить код | `python georag.py test` |
| Остановить базу | `python georag.py stop` |

Порядок всегда один: **добыть → почистить → загрузить → разметить → искать.**

## 2. Добыча статей — все ключи

```
.venv\Scripts\python -m georag.acquire.cli "выделение рудных узлов" --max-docs 5 --no-ocr --device cuda --mailto ваш@адрес --model qwen3:14b
```

По всем темам сразу — вместо темы в кавычках `--topics topics.yaml`.

| Ключ | Зачем |
|---|---|
| `--topics topics.yaml` | взять список тем из файла вместо одной темы |
| `--max-docs 5` | сколько статей разбирать за тему |
| `--no-ocr` | не распознавать картинки — быстрее в разы, для обычных статей не нужно |
| `--device cuda` | считать на видеокарте |
| `--mailto ...` | вежливый режим OpenAlex и Crossref: ответы стабильнее |
| `--model qwen3:14b` | какая модель в Ollama отбирает статьи |
| `--no-llm` | не спрашивать модель, решать эвристикой (когда Ollama выключена) |
| `--dry-run` | только поиск и отбор, без разбора — быстрая проверка |
| `--force` | не пропускать статьи, которые уже видели |
| `--tables fast` | быстрый разбор таблиц вместо точного |
| `--per-query 25` | сколько результатов брать из каждого источника |

Только запросы, без поиска — посмотреть, что модель придумала по теме:

```
.venv\Scripts\python -m georag.acquire.cli "рудные узлы" --queries-only
.venv\Scripts\python -m georag.acquire.cli --topics topics.yaml --queries-only --save-queries queries.yaml
```

Файл `queries.yaml` можно править руками, а потом искать по нему, не
спрашивая модель каждый раз:

```
.venv\Scripts\python -m georag.acquire.cli --topics topics.yaml --queries-file queries.yaml
```

## 3. Поиск — все ключи

```
.venv\Scripts\python -m georag.index.cli search "гидротермальные изменения ASTER" --limit 10 --per-doc 2 --year-from 2015
```

| Ключ | Зачем |
|---|---|
| `--limit 10` | сколько результатов показать |
| `--per-doc 2` | не больше N кусков одной статьи (0 — без ограничения) |
| `--year-from 2015` | только статьи не старше указанного года |
| `--source openalex` | искать только по одному источнику |
| `--candidates 50` | сколько кандидатов брать из каждого поиска до объединения |
| `--min-similarity 0.45` | отсечь непохожее: 0.45 — обычно, 0.55 — строго, 0 — показывать всё |
| `--require-words` | только куски, где буквально есть все слова запроса |
| `--embedder ollama` | считать вектор запроса через Ollama, а не на видеокарте |

Векторный поиск всегда возвращает ближайшее — даже когда подходящего в базе
нет. Поэтому есть порог `--min-similarity`. У BGE-M3 текст про то же самое
даёт похожесть примерно от 0.6, случайный сосед — около 0.3–0.45. Куски, где
буквально есть все слова запроса, проходят порог всегда.

У каждого результата написано, **кто его нашёл**: «вектор» — по смыслу,
«текст» — по точным словам, «оба» — согласились оба способа. «Оба» — самый
надёжный признак.

## 3а. Страница в браузере

```
python georag.py web
```

`http://localhost:8000`. Модель векторов грузится один раз при запуске, поэтому

Другой порт — `.venv\Scripts\python -m georag.web.server --port 9000`.

## 3б. Понятия и словарь

Словарь — `vocabulary.yaml`:

- **понятия** — восемь, копия справочника `kb.concept` из базы данных проекта.
  Коды менять нельзя: по ним ответ ложится в ту базу. Новое понятие сначала
  заводится там, потом переносится сюда вместе с определением;
- **синонимы** — слова, по которым понятие находится в тексте. Писать в любой
  форме: «окварцевание» найдёт и «окварцеванием». Английские тоже нужны;
- **территории** и **методы** — по ним фрагменты можно отбирать;
- **связи** — три, их строит код; в файле можно поменять только подпись.

Править Блокнотом, сохранять в UTF-8. После правки — `python georag.py graph`.

### Как размечается

Для каждого понятия его определение переводится в вектор и сравнивается со
всеми фрагментами базы; заодно фрагменты проверяются на слова словаря.
Фрагмент становится доказательством понятия, если он:

- близок к определению по смыслу — подпись **вектор**;
- содержит слово словаря и хоть сколько-то близок — **словарь**;
- и то и другое — **оба**, самый надёжный случай.

У каждого доказательства есть цитата — предложение из фрагмента, дословно.

### Пороги

Если у каждого понятия почти все статьи базы — пороги слишком мягкие. Если
почти ничего — слишком строгие. Подвинуть:

```
.venv\Scripts\python -m georag.graph.cli build --min-similarity 0.6 --min-similarity-terms 0.5
```

Обычные значения — 0.55 и 0.45. Выше — строже. `--max-per-concept 300` —
потолок фрагментов на одно понятие.

### Проверка моделью

```
python georag.py verify --limit 50
python georag.py verify
```

Модель отвечает на один вопрос: описывает ли фрагмент понятие по существу, и
если да — какой дословной фразой. **Фразу код ищет во фрагменте сам.** Нет её
там — модель переспрашивается один раз, не нашлась и тогда — фрагмент
отклоняется. Так выдумка модели не проходит.

Две-три секунды на фрагмент. Прервать можно в любой момент (Ctrl+C) —
следующий `verify` продолжит с того же места. Решения модели переживают
повторный `graph`. Нужна работающая Ollama с `qwen3:14b`.

### Граф связей

Вкладка «Граф связей»: в центре понятия, слева территории, справа методы.
Линия — есть фрагмент статьи, который описывает понятие и называет эту
территорию или этот метод. Толщина — число таких статей. Серые узлы — по ним
в корпусе ничего нет. Щелчок по линии открывает статьи с цитатами.

Внизу вкладки «Понятия» — **названия, найденные правилами** («…ский рудный
узел», «…ское рудопроявление»): обзор того, что упоминается в корпусе.

Из терминала:

```
.venv\Scripts\python -m georag.graph.cli top
.venv\Scripts\python -m georag.graph.cli top --kind метод
.venv\Scripts\python -m georag.graph.cli entity "Анабарский щит"
```

## 3в. Для базы данных проекта

Сервер — тот же, что открывает `python georag.py web`; для моста удобнее
`python georag.py serve` — без браузера. Спрашивает скрипт
`scripts/db_kb_evidence.py` из репозитория базы данных — как запускать, в
`ЗАПУСК.md`, раздел 6.

```
POST http://localhost:8000/api/concept
{"concept": "гидротермальные изменения", "territory": "Билляхская зона", "limit": 5}
```

| Поле | Зачем |
|---|---|
| `concept` | код понятия из `kb.concept` — обязательно |
| `territory` | территория из словаря, можно синонимом: `Billyakh` |
| `method` | метод из словаря |
| `limit` | сколько фрагментов, 1–100, по умолчанию 5 |
| `per_doc` | не больше стольких из одной статьи, по умолчанию 2 |
| `checked_only` | `true` — только подтверждённое моделью |

В ответе — фрагменты с цитатой, DOI, страницей, похожестью, пометкой «кто
нашёл» и решением модели; `total` и `documents` — сколько всего фрагментов и
статей подходит. Текста от себя база знаний не пишет.

| Адрес | Что отдаёт |
|---|---|
| `GET /api/concepts` | словарь и сколько доказательств у каждого понятия — по нему та сторона сверяет коды |
| `GET /api/graph` | схема: понятия — территории — методы |
| `GET /api/network` | сеть знаний: статьи и всё, о чём они |
| `GET /api/concept?concept=магматизм` | то же, что POST, — проверить руками в браузере |

С другой машины — только через SSH-туннель.

## 4. База в Docker

```
docker compose up -d          # поднять (первый раз — создаёт)
docker compose stop           # остановить, данные остаются
docker compose ps             # что сейчас работает
docker compose logs db        # что пишет база, если не поднимается
```

**Никогда:** `docker compose down -v` — удаляет том с базой, и всё придётся
загружать заново.

Перезагрузить всё в базу с нуля, не трогая добытые статьи:

```
python georag.py ingest --force
```

## 5. Ollama

Ollama отвечает за языковую работу: запросы к источникам, отбор статей и
проверку разметки (`verify`). Векторы считаются на видеокарте без неё.

```
ollama list                   # какие модели скачаны
ollama pull qwen3:14b         # основная модель
ollama pull bge-m3            # нужна, только если считать векторы через Ollama (--ollama)
ollama ps                     # что сейчас в памяти
ollama stop qwen3:14b         # выгрузить из видеопамяти
```

Модель выгружается сама примерно через пять минут простоя.

Модель, адрес почты и имя ночной задачи задаются в начале `georag.py`,
в блоке «настройки проекта».

